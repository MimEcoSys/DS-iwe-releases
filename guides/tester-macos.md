# Инструкция тестировщику на macOS

Ты проверяешь сборку-кандидат шаблона IWE до того, как её получат все пользователи, и пробуешь её сломать. Твой отчёт решает, выходит ли выпуск. Ты не автор этого кода, поэтому твой взгляд и нужен.

**Сейчас проверяем:** кандидат `v0.42.0-rc.3` ([сборка](https://github.com/TserenTserenov/FMT-exocortex-template/tree/v0.42.0-rc.3)), прошлый выпуск — `v0.41.11`.
**Время:** 3–4 часа, можно в два захода (после шага 5 и после шага 8).
**Что понадобится:** Мак, аккаунт GitHub, свой аккаунт Claude с подпиской Max (для шага 9 нужна самая сильная модель).

**Если что-то не так или непонятно** — остановись и напиши Выпускающему (TserenTserenov) в Telegram: номер шага, что ожидал, что увидел, снимок экрана. Не чини сам: несовпадение с инструкцией — тоже результат. Ты проходишь эту инструкцию первым, поэтому любое расхождение с экраном особенно ценно.

## Правила безопасности

1. **Всё делай в отдельной учётной записи Мака** (шаг 1), не в своей. Тест не тронет твои файлы, а после проверки запись удаляется целиком.
2. Установка создаст в твоём GitHub приватный репозиторий `DS-strategy` — после проверки его можно удалить.
3. Никаких паролей и ключей в отчёте и на снимках экрана.

## Шаг 1. Подготовка (30–40 мин, один раз)

1. **Учётная запись:** «Системные настройки» → «Пользователи и группы» → «Добавить пользователя», имя `iwe-test`, тип «Администратор». Выйди из своей записи и войди в `iwe-test`.
2. **Терминал:** Cmd+Пробел → «Терминал». Дальше каждую строку команд вставляй и запускай отдельно.
3. **Программы:**
   ```bash
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   brew install git node gh jq python
   npm install -g @anthropic-ai/claude-code
   gh auth login        # GitHub.com → HTTPS → Login with a web browser
   ```
4. **VS Code:** скачай с [code.visualstudio.com](https://code.visualstudio.com), открой, Cmd+Shift+X → найди «Claude Code» → Install. Войди в свой аккаунт Claude.
5. **Номера версий** — чтобы дальше копировать команды как есть:
   ```bash
   echo 'export RC=v0.42.0-rc.3 PREV=v0.41.11' >> ~/.zshrc && source ~/.zshrc
   ```

## Шаг 2. Прошлый выпуск — основа для проверки обновления (15 мин)

```bash
mkdir -p ~/IWE && cd ~/IWE
git clone --branch "$PREV" https://github.com/TserenTserenov/FMT-exocortex-template.git
cd FMT-exocortex-template
bash setup.sh
```

На вопросы установки: логин GitHub — свой, остальное — Enter. Затем две «свои правки» (проверим, что обновление их не сотрёт) и копия установки:

```bash
echo "# моя правка для проверки" >> ~/IWE/extensions/test-marker.md
echo "test_marker: keep-me" >> ~/IWE/params.yaml
cp -R ~/IWE ~/IWE-prev-copy && cp -R ~/.claude ~/.claude-prev-copy
```

## Шаг 3. Обновление на кандидата (10 мин)

```bash
cd ~/IWE/FMT-exocortex-template
IWE_UPDATE_CHANNEL=rc bash update.sh
```

**Пройдено, если:** в выводе есть строка `Канал поставки: кандидат v0.42.0-rc.3`; обновление дошло до конца без ошибки; команды `cat ~/IWE/extensions/test-marker.md` и `grep test_marker ~/IWE/params.yaml` показывают твои правки; повторный запуск той же команды ничего не меняет.

## Шаг 4. Открытие дня и репетиция закрытия (15 мин)

В VS Code: «Файл» → «Открыть папку» → `~/IWE`. Открой панель Claude Code и напиши `открывай`. Когда план дня собран, напиши `/audit-installation` и дойди до шага 2.5 (репетиция закрытия дня).

**Пройдено, если:** открытие дня собрало план дня; репетиция дошла до первой записи и там остановилась сама.

## Шаг 5. Объяснение изменений агентом (10 мин)

Верни копию прошлого выпуска:

```bash
rm -rf ~/IWE ~/.claude && cp -R ~/IWE-prev-copy ~/IWE && cp -R ~/.claude-prev-copy ~/.claude
```

В VS Code открой `~/IWE`, новая беседа Claude Code: `/iwe-update`; на вопрос о канале — кандидат.

**Пройдено, если:** агент объясняет изменения кандидата 0.42 (а не последние правки основной ветки), и в объяснении нет служебных полей «Цель», «Как проверить», «Как откатить».

## Шаг 6. Чистая установка кандидата (15 мин)

```bash
rm -rf ~/IWE ~/.claude
mkdir -p ~/IWE && cd ~/IWE
git clone --branch "$RC" https://github.com/TserenTserenov/FMT-exocortex-template.git
cd FMT-exocortex-template
bash setup.sh
bash update.sh --check
```

**Пройдено, если:** установка завершилась; проверка пишет `ВЕРДИКТ: можно ставить` или «всё актуально».

Шаги 7 и 8 делай на этой установке **до** того, как напишешь агенту «открывай»: открытие дня делает установку «рабочей», и онбординг для нового человека больше не включится.

## Шаг 7. Лёгкий онбординг нового человека (20 мин)

В VS Code открой `~/IWE`, новая беседа Claude Code. Веди себя как новичок: напиши `с чего начать?`, затем опиши свою небольшую настоящую задачу и отвечай на вопросы агента.

**Пройдено, если:** агент не просит войти в аккаунт, оформить подписку или завести рабочий продукт; разговор доходит до итога «было → стало» по твоей задаче. Если спросить «Это платно? Надо регистрироваться?» — агент отвечает, что этот разговор не требует ни аккаунта, ни подписки.

## Шаг 8. Навык поиска метода `/find-method` (15 мин)

Три запроса, каждый — в **новой** беседе Claude Code в `~/IWE`:

1. `/find-method как вывести закваску для хлеба` → **пройдено,** если агент честно говорит, что метода нет, и не выдумывает план.
2. `/find-method нужно ли мне исследование, чтобы ответить на мой вопрос, или хватит того, что уже известно` → **пройдено,** если среди кандидатов есть `RMP.1` и агент просит выбрать (выбирать за тебя он не должен — ответь «RMP.1»); после выбора он показывает все 8 шагов раздела `RMP.1:4.1` английским текстом, как в источнике, а русское пояснение даёт после цитаты. Пересказ шагов по-русски вместо цитаты — «не пройдено».
3. `/find-method подскажи метод, у меня проблема с проектом` → **пройдено,** если агент сначала задаёт один уточняющий вопрос и только потом ищет.

## Шаг 9. Red team — независимая атака (1–1,5 ч)

Ты пробуешь сломать кандидата так, как это сделал бы злоумышленник или неудачное обновление. Атаку ведёт агент по готовому методу, ты запускаешь и следишь.

1. В VS Code открой папку `~/IWE/FMT-exocortex-template`. **Новая** беседа Claude Code, модель — самая сильная из доступных.
2. Напиши:
   ```
   /iwe-platform-redteam проверь кандидат выпуска v0.42.0-rc.3: чистая установка, обновление с v0.41.11, возврат, права агента, защитные проверки. Только одноразовые копии во временной папке.
   ```
3. Агент сначала проверит себя на двух учебных сборках: плохую обязан заблокировать, хорошую — пропустить. Не вышло — он скажет `cannot_verify`. Это тоже результат, впиши как есть.
4. Просит разрешения на команду — разрешай только то, что работает во временной папке (путь начинается с `/var/folders` или `/tmp`). Всё, что трогает `~/IWE` или `~/.claude`, — отклоняй.
5. В конце будет раздел `## Verdict` с одним словом: `GO`, `CAUTION` или `BLOCKED`. Попроси агента сохранить весь отчёт в файл `~/redteam-report.md`.
6. Подпись того, что ты проверял именно этого кандидата (40 символов — в отчёт):
   ```bash
   git -C ~/IWE/FMT-exocortex-template rev-parse "v0.42.0-rc.3^{tree}"
   ```

## Шаг 10. Отчёт и уборка

Скопируй образец в файл `~/rc.3.yaml`, у каждой проверки впиши `пройдено`, `не пройдено` или `не проверялось`, в `note` — что увидел (без имён и личных данных):

```yaml
build: 0.42-rc.3
marks:
  - {line: 2,  result: , tester: <твой логин GitHub>, note: ""}   # шаг 3 — обновление на кандидата
  - {line: 5,  result: , tester: <твой логин GitHub>, note: ""}   # шаг 4 — открытие дня и репетиция
  - {line: 10, result: , tester: <твой логин GitHub>, note: ""}   # шаг 5 — объяснение изменений
  - {line: 1,  result: , tester: <твой логин GitHub>, note: ""}   # шаг 6 — чистая установка
  - {line: 17, result: , tester: <твой логин GitHub>, note: ""}   # шаг 7 — лёгкий онбординг
  - {line: 18, result: , tester: <твой логин GitHub>, note: ""}   # шаг 8 — /find-method, три запроса
red_team:                                                        # шаг 9
  verdict:                       # GO | CAUTION | BLOCKED | cannot_verify
  checker: <твой логин GitHub>
  report: redteam-report.md
  tree:                          # 40 символов из шага 9, пункт 6
```

Перед отправкой открой `~/redteam-report.md` и убедись, что в нём нет паролей, ключей и путей с твоим настоящим именем пользователя. Пришли оба файла (`rc.3.yaml` и `redteam-report.md`) Выпускающему в Telegram — в репозиторий их перенесёт Разработчик без правок.

**Уборка:** удали учётную запись `iwe-test` («Пользователи и группы» → «−») и, если хочешь, репозиторий `DS-strategy` в своём GitHub.
