# Инструкция тестировщику на macOS

Ты проверяешь новую версию IWE до того, как её получат все, и пробуешь её сломать. Твой отчёт решает, выходит ли выпуск.

**Сейчас проверяем:** кандидат `v0.42.0-rc.15` ([сборка](https://github.com/TserenTserenov/FMT-exocortex-template/tree/v0.42.0-rc.15)), прошлый выпуск `v0.41.11`. Если ты начал на прошлом кандидате, начни заново с шага 1: отметки прошлой сборки не переносятся.

**Время:** 3–4 часа, можно в два захода: перерыв после шага 5 или после шага 8.

**Что понадобится:** Мак, аккаунт GitHub, аккаунт Claude с подпиской Max (для шага 9 нужна самая сильная модель).

**Если что-то не так или непонятно**, остановись и напиши Выпускающему (TserenTserenov) в Telegram: номер шага, что ожидал, что увидел, снимок экрана (Cmd+Shift+4, затем выделить область). Не чини сам: несовпадение с инструкцией — тоже результат.

**Как читать команды.** Каждая команда стоит в своей серой рамке. Справа у рамки есть кнопка копирования: нажми её, вставь в Терминал (Cmd+V) и нажми Enter. Дождись, пока команда закончит работу и снова появится строка с `%` в конце, и только тогда бери следующую.

**Правила безопасности**
1. Всё делай в отдельной учётной записи Мака (шаг 1), не в своей. Тест не тронет твои файлы, а после проверки запись удаляется целиком.
2. Установка создаст в твоём GitHub закрытое хранилище `DS-strategy`. После проверки его можно удалить.
3. Никаких паролей и ключей в отчёте и на снимках экрана.

<details open><summary><b>Шаг 1. Подготовка (30–40 мин, один раз)</b></summary>

**1.1. Отдельная учётная запись Мака**

1. Нажми на яблоко  в левом верхнем углу экрана и выбери «Системные настройки».
2. В левой колонке окна выбери «Пользователи и группы».
3. Нажми кнопку «Добавить пользователя…» внизу справа. Мак попросит пароль от твоей учётной записи — введи его.
4. В окне новой записи заполни поля:
   - «Новая учётная запись» — «Администратор»;
   - «Полное имя» и «Имя учётной записи» — `iwe-test`;
   - «Пароль» — любой, запомни его: он понадобится дальше.
5. Нажми «Создать пользователя».
6. Нажми на яблоко  → «Завершить сеанс…» → «Завершить сеанс». На экране входа выбери `iwe-test` и введи его пароль. Первый вход задаст несколько вопросов (Apple ID, Siri, аналитика) — везде можно выбрать «Не сейчас» или «Пропустить».

Всё дальше делай в записи `iwe-test`.

**1.2. Открыть Терминал**

Нажми Cmd+Пробел — посередине экрана появится строка поиска. Напиши в ней `Терминал` (или `Terminal`) и нажми Enter. Откроется окно с текстом и строкой, которая заканчивается на `%`. В это окно ты будешь вставлять команды.

**1.3. Установить нужные программы**

Вставляй эти команды в Терминал по одной.

Менеджер программ Homebrew:

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

Он попросит пароль учётной записи `iwe-test`. При вводе пароль не виден, даже звёздочек нет — это нормально, просто введи его и нажми Enter. Затем он попросит нажать Enter ещё раз. Установка идёт 5–10 минут.

Если в конце Homebrew напишет «Next steps» и покажет команды с `brew shellenv`, выполни эти две (на Маке с процессором Apple; на Маке с Intel они не нужны, но и не навредят):

```bash
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
```

```bash
eval "$(/opt/homebrew/bin/brew shellenv)"
```

Git, Node, GitHub, jq и Python:

```bash
brew install git node gh jq python
```

Claude Code:

```bash
npm install -g @anthropic-ai/claude-code
```

Вход в GitHub:

```bash
gh auth login
```

Программа задаст несколько вопросов. Стрелками выбирай ответ и нажимай Enter:
- «Where do you use GitHub?» — `GitHub.com`;
- «What is your preferred protocol?» — `HTTPS`;
- «Authenticate Git with your GitHub credentials?» — `Yes`;
- «How would you like to authenticate?» — `Login with a web browser`.

Программа покажет код из 8 знаков. Скопируй его и нажми Enter: откроется браузер. Войди в GitHub, вставь код и нажми «Authorize». В Терминале должно появиться «Logged in as <твой логин>».

**1.4. VS Code и Claude Code в нём**

1. Открой в браузере [code.visualstudio.com](https://code.visualstudio.com) и нажми «Download for macOS».
2. Открой скачанный файл в папке «Загрузки». Если появится программа Visual Studio Code, перетащи её в папку «Программы».
3. Открой VS Code через Cmd+Пробел → `Visual Studio Code` → Enter.
4. Нажми Cmd+Shift+X — слева откроется список расширений. В строке поиска над ним напиши `Claude Code` и нажми синюю кнопку «Install» у расширения от Anthropic.
5. Слева появится значок Claude Code. Нажми его и войди в свой аккаунт Claude: кнопка «Sign in» откроет браузер.

**1.5. Запомнить номера версий**

Вернись в Терминал (Cmd+Пробел → `Терминал` → Enter) и выполни:

```bash
echo 'export RC=v0.42.0-rc.15 PREV=v0.41.11' >> ~/.zshrc && source ~/.zshrc
```

Теперь дальнейшие команды можно копировать как есть.

<details><summary><b>Шаг 3. Обновить на кандидата (10 мин)</b></summary>

В Терминале:

```bash
cd ~/IWE/FMT-exocortex-template
```

```bash
IWE_UPDATE_CHANNEL=rc bash update.sh
```

Обновление покажет, что изменится, и спросит «Применить обновления? (y/n)». Нажми `y`.

Проверь, что правки на месте, — каждая команда должна показать твою строку:

```bash
cat ~/IWE/extensions/test-marker.md
```

```bash
grep test_marker ~/IWE/params.yaml
```

Запусти обновление ещё раз:

```bash
IWE_UPDATE_CHANNEL=rc bash update.sh
```

**Пройдено, если:**
- в выводе первого запуска есть строка `Канал поставки: кандидат v0.42.0-rc.15`;
- обновление дошло до конца без строки «ОШИБКА»;
- обе проверки показали твои правки;
- второй запуск пишет «Всё актуально».

</details>

<details><summary><b>Шаг 4. Открытие дня и репетиция закрытия (15 мин)</b></summary>

1. В VS Code: меню «File» (или «Файл») → «Open Folder…» (или «Открыть папку…»).
2. В окне выбора нажми Cmd+Shift+G, напиши `~/IWE` и нажми Enter, затем кнопку «Open» (или «Открыть»). Если VS Code спросит, доверяешь ли ты авторам, нажми «Yes, I trust the authors».
3. Слева нажми значок Claude Code — откроется окно разговора.
4. Напиши в нём `открывай` и нажми Enter. Агент соберёт план дня; на вопросы о разрешениях отвечай «Allow» (разрешить).
5. Когда план готов, напиши `/audit-installation` и нажми Enter. Агент проверит установку и на шаге 2.5 начнёт репетицию закрытия дня.

**Пройдено, если:** агент собрал план дня, а репетиция дошла до первой записи и там остановилась сама.

</details>

<details><summary><b>Шаг 5. Объяснение изменений агентом (10 мин)</b></summary>

Работай на той же установке, которую обновил на шаге 3; копию прошлого выпуска не возвращай.

1. В окне Claude Code начни новый разговор: значок «+» (New conversation) вверху окна.
2. Напиши и отправь:

```
/iwe-update что изменилось в установленном выпуске по сравнению с 0.41.11?
```

Если агент ответит «обновлять нечего» и ничего не объяснит, запиши это и спроси ещё раз: «что изменилось в установленном выпуске?».

**Пройдено, если:** агент объясняет изменения 0.42 простыми словами, и в объяснении нет служебных пометок «Цель», «Как проверить», «Как откатить».

Здесь можно сделать перерыв.

</details>

<details><summary><b>Шаг 7. Знакомство нового человека с IWE (20 мин)</b></summary>

1. Открой VS Code и папку `~/IWE`, как на шаге 4 (пункты 1–3).
2. В окне Claude Code напиши `с чего начать?` и отправь.
3. Веди себя как новичок: опиши свою небольшую настоящую задачу и отвечай на вопросы агента.
4. В какой-то момент спроси: «Это платно? Надо регистрироваться?»

**Пройдено, если:**
- агент не просит войти в аккаунт, оформить подписку или завести рабочий продукт;
- на вопрос про оплату отвечает, что этот разговор не требует ни аккаунта, ни подписки;
- разговор доходит до итога «было → стало» по твоей задаче.

</details>

<details><summary><b>Шаг 8. Поиск метода (15 мин)</b></summary>

Три запроса, каждый в **новом** разговоре Claude Code (значок «+» вверху окна).

Первый:

```
/find-method как вывести закваску для хлеба
```

**Пройдено, если** агент честно говорит, что подходящего метода нет, и не выдумывает план.

Второй:

```
/find-method нужно ли мне исследование, чтобы ответить на мой вопрос, или хватит того, что уже известно
```

**Пройдено, если** среди предложенных есть `RMP.1` и агент просит выбрать сам, а не выбирает за тебя. Ответь `RMP.1`. После этого агент показывает все 8 шагов раздела `RMP.1:4.1` по-английски, как в источнике, а русское пояснение даёт после цитаты. Если вместо цитаты агент пересказал шаги по-русски — «не пройдено».

Третий:

```
/find-method подскажи метод, у меня проблема с проектом
```

**Пройдено, если** агент сначала задаёт один уточняющий вопрос и только потом ищет.

Здесь можно сделать перерыв.

</details>

<details><summary><b>Шаг 9. Атака на сборку (1–1,5 ч)</b></summary>

Ты пробуешь сломать кандидата так, как это сделал бы злоумышленник или неудачное обновление. Атаку ведёт агент по готовому навыку, ты запускаешь и следишь.

1. В VS Code открой папку `~/IWE/FMT-exocortex-template` (как на шаге 4, только в окне выбора напиши `~/IWE/FMT-exocortex-template`).
2. В окне Claude Code начни новый разговор (значок «+»).
3. Выбери самую сильную модель: напиши `/model`, отправь и выбери в списке Opus.
4. Скопируй и отправь:

```
/iwe-platform-redteam проверь кандидат выпуска v0.42.0-rc.15: чистая установка, обновление с v0.41.11 и с v0.36.3, возврат, права агента, защитные проверки. Только одноразовые копии во временной папке.
```

5. Агент сначала проверит себя на двух учебных сборках: плохую он обязан остановить, хорошую — пропустить. Если не получится, он скажет `cannot_verify` — это тоже результат, запиши как есть.
6. Агент будет спрашивать разрешение на команды. Нажимай «Allow» только для команд, где путь начинается с `/var/folders` или `/tmp`. Всё, что трогает `~/IWE` или `~/.claude`, отклоняй кнопкой «Deny».
7. В конце будет раздел `## Verdict` с одним словом: `GO`, `CAUTION` или `BLOCKED`. Напиши агенту: «сохрани весь отчёт в файл ~/redteam-report.md».
8. Узнай подпись сборки: 40 знаков, по которым видно, что ты проверял именно rc.15. В Терминале:

```bash
git -C ~/IWE/FMT-exocortex-template rev-parse "v0.42.0-rc.15^{tree}"
```

Скопируй эти 40 знаков, они понадобятся в шаге 10.

</details>

<details><summary><b>Шаг 10. Отчёт и уборка</b></summary>

**10.1. Заполнить файл отметок**

1. В VS Code: меню «File» → «New Text File» (или «Файл» → «Новый текстовый файл»).
2. Скопируй в него образец ниже.
3. В каждой строке после `result:` впиши `пройдено`, `не пройдено` или `не проверялось`, в `note` — пару слов о том, что увидел (без имён и личных данных). Вместо `<твой логин GitHub>` впиши свой логин. В `tree` вставь 40 знаков из шага 9, а в `verdict` — слово из раздела `## Verdict`.
4. Сохрани: Cmd+S, в окне сохранения нажми Cmd+Shift+G, напиши `~` и нажми Enter, имя файла — `macos-<твой логин GitHub>.yaml`, кнопка «Save».

```yaml
build: 0.42-rc.15
marks:
  - {line: 2,  result: , tester: <твой логин GitHub>, note: ""}   # шаг 3 — обновление на кандидата
  - {line: 5,  result: , tester: <твой логин GitHub>, note: ""}   # шаг 4 — открытие дня и репетиция
  - {line: 10, result: , tester: <твой логин GitHub>, note: ""}   # шаг 5 — объяснение изменений
  - {line: 1,  result: , tester: <твой логин GitHub>, note: ""}   # шаг 6 — чистая установка
  - {line: 17, result: , tester: <твой логин GitHub>, note: ""}   # шаг 7 — знакомство нового человека
  - {line: 18, result: , tester: <твой логин GitHub>, note: ""}   # шаг 8 — поиск метода, три запроса
red_team:                                                        # шаг 9
  verdict:                       # GO | CAUTION | BLOCKED | cannot_verify
  checker: <твой логин GitHub>
  report: redteam-macos.md
  tree:                          # 40 знаков из шага 9
```

**10.2. Проверить отчёт атаки и отправить**

1. Открой в VS Code файл `~/redteam-report.md` («File» → «Open File…», Cmd+Shift+G, `~/redteam-report.md`).
2. Убедись, что в нём нет паролей, ключей и путей с твоим настоящим именем пользователя.
3. Пришли оба файла (`macos-<логин>.yaml` и `redteam-report.md`) Выпускающему в Telegram. Разработчик без правок положит их в [папку кандидата rc.15](../releases/0.42/tests/README.md). Если ты в команде `iwe-testers`, можешь сам открыть запрос на слияние в папку `releases/0.42/tests/rc.15/`.

**10.3. Уборка**

1. Нажми на яблоко  → «Завершить сеанс…» и войди в свою обычную учётную запись.
2. Яблоко  → «Системные настройки» → «Пользователи и группы» → нажми на `iwe-test` → «Удалить пользователя…» → выбери «Удалить домашнюю папку» → «Удалить пользователя».
3. По желанию удали хранилище `DS-strategy` в своём GitHub: на его странице «Settings» → в самом низу «Delete this repository».

</details>

*Для команды выпуска:* номера `line` — строки [протокола выпуска 0.42](../releases/0.42/protocol.md); формат отметок — [tests/README.md](../releases/0.42/tests/README.md). Строки 3, 4, 11, 12, 15 — у Разработчика; 6–9 — Windows и Linux; 14 и 16 в эту инструкцию не вошли.
