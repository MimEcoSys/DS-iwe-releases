# Инструкция тестировщику на macOS

> **Статус: черновик.** Разработчик проходит эти шаги сам на ближайшем кандидате и исправляет то, что не совпадёт с экраном. До этой отметки по инструкции не работать: _прогон Разработчика — не сделан_.

Ты проверяешь сборку-кандидат шаблона IWE до того, как её получат все пользователи, и пробуешь её сломать. Твой отчёт решает, выходит ли выпуск. Ты не автор этого кода, поэтому твой взгляд и нужен. Где эта работа стоит среди других этапов — в [листе этапов](release-process.md).

**Время:** 3–4 часа, можно в два захода. **Что понадобится:** Мак, VS Code, аккаунт GitHub, доступ к Claude (даст Выпускающий). **Что получишь от Выпускающего:** номер кандидата (например `v0.42.0-rc.1`), номер прошлого выпуска (например `v0.41.11`), ссылку на тему выпуска в Зулипе и номера своих строк в протоколе выпуска (`releases/<N>/protocol.md`, колонка «Кто»).

Ниже — как проходить типовые строки. Строки, особые для выпуска (новый навык, новый сценарий), описаны прямо в протоколе выпуска: там написано, что сделать и что считать пройденным.

## Правила безопасности

1. **Всё делай в отдельной учётной записи Мака**, не в своей. Так тест не тронет твои файлы, а после проверки запись можно удалить.
2. Установка IWE создаст в твоём GitHub приватный репозиторий `DS-strategy` и поставит фоновые задачи в этой учётной записи. После проверки репозиторий можно удалить; фоновые задачи удалятся вместе с учётной записью.
3. Шаг не совпадает с написанным — **остановись**, сделай снимок экрана и напиши в тему выпуска. Не чини сам: найденное несовпадение — тоже результат.
4. Никаких паролей и ключей в отчёт, в Зулип и в снимки экрана.

## Шаг 0. Подготовка (один раз, 30–40 мин)

1. **Новая учётная запись:** «Системные настройки» → «Пользователи и группы» → «Добавить пользователя», имя `iwe-test`, тип «Администратор». Выйди из своей записи и войди в `iwe-test`.
2. **Терминал:** Cmd+Пробел → «Терминал».
3. **Программы** — по очереди, каждую строку отдельно:
   ```bash
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   brew install git node gh jq python
   npm install -g @anthropic-ai/claude-code
   gh auth login        # GitHub.com → HTTPS → Login with a web browser
   ```
4. **VS Code:** скачай с code.visualstudio.com, открой, Cmd+Shift+X → найди «Claude Code» → Install. Войди в Claude тем доступом, что дал Выпускающий.
5. **Номера** запиши в переменные, чтобы дальше копировать команды как есть (подставь свои):
   ```bash
   echo 'export RC=v0.42.0-rc.1 PREV=v0.41.11' >> ~/.zshrc && source ~/.zshrc
   ```
   Новый кандидат (`rc.2`) — поменяй `RC` и пройди всё заново: отметки прошлого кандидата не переносятся.

## Шаг 1. Установка прошлого выпуска — основа для проверок обновления и возврата (15 мин)

```bash
mkdir -p ~/IWE && cd ~/IWE
git clone --branch "$PREV" https://github.com/TserenTserenov/FMT-exocortex-template.git
cd FMT-exocortex-template
bash setup.sh
```

На вопросы установки: логин GitHub — свой; остальное — Enter.

Сделай две «свои правки», чтобы потом проверить, что обновление их не стёрло:

```bash
echo "# моя правка для проверки" >> ~/IWE/extensions/test-marker.md
echo "test_marker: keep-me" >> ~/IWE/params.yaml
```

Сделай копию всей установки — это твой путь назад:

```bash
cp -R ~/IWE ~/IWE-prev-copy
cp -R ~/.claude ~/.claude-prev-copy
```

## Обновление с прошлого выпуска на кандидата

```bash
cd ~/IWE/FMT-exocortex-template
IWE_UPDATE_CHANNEL=rc bash update.sh
```

**Пройдено, если:**
- в выводе есть строка `Канал поставки: кандидат <номер кандидата>`;
- обновление дошло до конца без ошибки;
- `cat ~/IWE/extensions/test-marker.md` и `grep test_marker ~/IWE/params.yaml` показывают твои правки;
- повторный запуск той же команды ничего не меняет.

## Открытие дня на кандидате

В VS Code: «Файл» → «Открыть папку» → `~/IWE`. Открой панель Claude Code и напиши: `открывай`. Затем: `/audit-installation`, дойди до шага 2.5 (репетиция закрытия дня).

**Пройдено, если:** открытие дня собрало план дня; репетиция дошла до первой записи и там остановилась сама.

## Возврат на прошлый выпуск

```bash
cd ~/IWE/FMT-exocortex-template
bash update.sh
```

**Пройдено, если:** обновление называет это откатом и без подтверждения ничего не меняет. Затем подтверди (обновление попросит ввести `ROLLBACK`), после чего: версия снова прошлая, твои правки из шага 1 на месте.

## Объяснение изменений агентом

Верни копию прошлого выпуска и обнови её через агента:

```bash
rm -rf ~/IWE ~/.claude && cp -R ~/IWE-prev-copy ~/IWE && cp -R ~/.claude-prev-copy ~/.claude
```

В VS Code открой `~/IWE`, в панели Claude Code: `/iwe-update` (на вопрос о канале — кандидат).

**Пройдено, если:** агент объясняет изменения кандидата (а не последние правки основной ветки), и в объяснении нет служебных полей «Цель», «Как проверить», «Как откатить».

## Чистая установка кандидата

```bash
rm -rf ~/IWE ~/.claude
mkdir -p ~/IWE && cd ~/IWE
git clone --branch "$RC" https://github.com/TserenTserenov/FMT-exocortex-template.git
cd FMT-exocortex-template
bash setup.sh
bash update.sh --check
```

**Пройдено, если:** установка завершилась; проверка пишет `ВЕРДИКТ: можно ставить` или «всё актуально».

## Red team — независимая атака (1–1,5 ч)

Ты пробуешь сломать кандидата так, как это сделал бы злоумышленник или неудачное обновление. Делает это агент по готовому методу, ты запускаешь и следишь.

1. Нужна установка кандидата из раздела «Чистая установка кандидата». В VS Code открой папку `~/IWE/FMT-exocortex-template`. Открой **новую** беседу Claude Code — без истории прошлых шагов. Модель — самая сильная из доступных.
2. Напиши (вместо `<RC>` и `<PREV>` — номера):
   ```
   /iwe-platform-redteam проверь кандидат выпуска <RC>: чистая установка, обновление с <PREV>, возврат, права агента, защитные проверки. Только одноразовые копии во временной папке.
   ```
3. Агент сначала проверит себя на двух учебных сборках: заведомо плохую обязан заблокировать, заведомо хорошую — пропустить. Не вышло — он скажет `cannot_verify`. Это тоже результат: впиши как есть.
4. Если агент просит разрешения на команду, разрешай только то, что работает во временной папке (путь начинается с `/var/folders` или `/tmp`). Всё, что трогает `~/IWE` или `~/.claude`, — отклоняй.
5. В конце будет раздел `## Verdict` с одним словом: `GO`, `CAUTION` или `BLOCKED`. Попроси агента сохранить весь отчёт в файл `~/redteam-report.md`.
6. Узнай дерево кандидата — подпись того, что ты проверял именно его:
   ```bash
   git -C ~/IWE/FMT-exocortex-template rev-parse "$RC^{tree}"
   ```

## Отчёт

Заполни и отправь. Если ты в команде `iwe-testers` организации MimEcoSys — запросом на слияние в файл `releases/<N>/tests/rc.<K>.yaml` этого репозитория; если нет — файлом Выпускающему, и Разработчик перенесёт его без правок. Формат — `releases/<N>/tests/README.md` в папке твоего выпуска.

```yaml
build: 0.42-rc.1                 # твой кандидат
marks:
  - {line: 1, result: пройдено, tester: <твой логин GitHub>, note: ""}
  # по строке на каждую свою строку протокола;
  # result: пройдено | не пройдено | не проверялось; в note — что увидел, без имён и личных данных
red_team:                        # только если тебе назначена атака
  verdict: GO                    # GO | CAUTION | BLOCKED | cannot_verify — слово из раздела Verdict
  checker: <твой логин GitHub>
  report: <ссылка на файл отчёта или на комментарий в запросе на слияние>
  tree: <40 символов из раздела Red team, пункт 6>
```

Отчёт red team (`~/redteam-report.md`) приложи целиком. Перед отправкой открой его и убедись, что там нет паролей, ключей и путей с твоим настоящим именем пользователя.

## После проверки

Удали учётную запись `iwe-test` («Пользователи и группы» → «−») и, если хочешь, репозиторий `DS-strategy` в своём GitHub.
