# DS-iwe-releases — правила для ИИ-агентов

Открытый репозиторий команды выпуска шаблона IWE. Суть, роли и порядок работы — в README.md.

## Обязательно загружай

Перед работой в роли выпуска — прочитай [guides/release-process.md](guides/release-process.md) и инструкцию своей роли: Выпускающему — [guides/release-lead-start.md](guides/release-lead-start.md) и [guides/release-lead.md](guides/release-lead.md), затем `releases/<N>/README.md` текущего выпуска, тестировщику — [guides/tester-macos.md](guides/tester-macos.md). Роль и метод — в Паке (DP.ROLE.120); расходится — прав Пак.

## Обязательно

- **Без личных данных.** Людей указывать только логином GitHub; почту, телефоны, обращения пользователей с их данными не писать. Обращение пользователя — пересказом без имени. Секретов и ключей здесь нет и не будет.
- **Только свой файл роли.** Агент Разработчика правит `ops/developer-links.yaml`, `ops/developer-handoff.yaml` и `releases/<N>/README.md`, Выпускающего — `releases/<N>/decisions.md`, тестировщика — `releases/<N>/tests/`. Чужой файл не трогать.
- **`BOARD.md`, `board/`, `ops/snapshot.yaml`, `releases/<N>/shipped.md` и `releases/<N>/candidates.md` руками не править** — их собирает программа `ops/build_board.py`. `BOARD.md` и `board/` — оперативное, переписываются целиком; `releases/<N>/` — накопительное, после выхода выпуска не меняется.
- **Статус — только из закрытого списка** в README, раздел «Стадии и статусы». Новый статус — сначала правка README через запрос на слияние.
- **Все правки — через запрос на слияние**, не прямой отправкой в main.
- Номера целей и коды результатов не придумывать: цели — из «Целей и сценариев» (DP.MAP.005), коды — из «Состояния по целям».
