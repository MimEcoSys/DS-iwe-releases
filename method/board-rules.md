# Правила счёта и статусов табло

Страница для команды выпуска: как считается табло и какие бывают статусы. Пользователю нужен [каталог выпусков](../releases/INDEX.md).

## Табло и его числа

**[Табло](../board/README.md)** — сводка всех результатов закреплённого снимка по четырём стадиям с учётом подробных статусов подготовки выпуска. Числа не пишутся руками: их собирает программа, они стоят на табло и на странице «что сейчас» ([NOW.md](../NOW.md)). Разница с исходными стадиями — в [сверке](../board/completeness.md). Что вошло в выпуски шаблона: [до 0.36](../releases/0.N/0.36/shipped.md), [0.37–0.41.11](../releases/0.N/0.41.11/shipped.md).

**Как обновляется.** Сейчас — по запуску: Разработчик запускает программу `tools/build_board.py`, она заново читает закреплённый снимок исходного документа, шаблон и файлы Разработчика и пересобирает табло и рабочие списки. В табло указана дата состояния результатов; в списках подготовки — версия шаблона. Следующий шаг — сборщик в GitHub Actions: пересборка раз в час и при каждой правке, при сбое — автоматическая задача, а старый вид остаётся со своей датой (ещё не сделан).

**Выпуск** — публикация определённой версии шаблона пользователям, например 0.42. Это отдельная работа команды; общий счёт результатов не ограничен её выбором.


## Единицы счёта

| Единица | Что это | Откуда |
|---|---|---|
| **Цель** | чего хочет человек и по чему видно, что цель достигнута | [«Цели и сценарии»](https://github.com/MimEcoSys/PACK-digital-platform/blob/main/pack/digital-platform/07-map/DP.MAP.005-mcp-scenarios.md) |
| **Обещанный результат** | конкретная вещь, которую работа обещает человеку под одну цель; постоянный код «Ц<цель>-<номер>» | «Состояние по целям» (закрытый репозиторий; код и короткий текст перенесены в файл Разработчика снимком) |
| **Запись списка изменений** | строка `CHANGELOG.md` шаблона об одной правке | список изменений шаблона |
| **Запись обкатки** | строка `STAGING.md` Разработчика о поведении, которое он проверяет на себе | `STAGING.md` (закрытый репозиторий) |
| **Выпуск** | версия шаблона, которую получают пользователи: 0.36.3, 0.41.11, 0.42 | метки выпусков шаблона |

**Табло считает только обещанные результаты.** Сводная таблица и детализация используют одни статусы: исходную стадию уточняет подтверждённый статус подготовки выпуска. Записи правок — для справки: результат продвигается по этапам подготовки, когда в шаблон, в отбор или в выпуск вошли все его записи. Запись, ещё не связанная с результатом, видна отдельно и в счёт не идёт.

## Стадии и статусы

На [табло](../board/README.md) четыре стадии: план, в работе, сделано, отложено. Каждый код учитывается один раз. По умолчанию используется стадия источника; «в работе» соответствует этапу 2.1. Это правило одинаково для всех направлений и систем. Если для результата уже подтверждён более подробный статус проверки, передачи или принятия в выпуск, используется он — вместе с родительской стадией «В работе».

Результаты, у которых источник говорит «в работе», целиком стоят на этапе 2.1. У части результатов источник содержит отметку «сделано», а подробный учёт выпуска — этапы 2.2–2.4: в общем табло они учитываются в пункте 2, а не одновременно в пунктах 2 и 3. Исходные отметки не переписываются: числа и все такие коды показаны в [сверке](../board/completeness.md).

### Как определяется стадия

Страницы в `board/` показывают полный состав соответствующих стадий. Для плана, сделанного и отложенного хранятся коды, состояния и ссылки на исходные описания; для пункта 2 сохранены рабочие пояснения. Сборка сверяет не только суммы, но и каждый код. Ссылки ведут к закреплённой версии исходного документа: изменения источника появятся после следующей пересборки.

Этапы 2.1–2.4 не пересекаются, их сумма обязана совпадать с пунктом 2; иначе сборка останавливается. Неизвестный программе статус также останавливает сборку. Ссылки с чисел ведут только к кодам соответствующей группы.

| Стадия | Статусы | Что значит | Кто ставит |
|---|---|---|---|
| **1. План** | `план` | результат обещан, работа не начата | Разработчик |
| **2. В работе** | | сумма этапов 2.1–2.4 для всех результатов | |
| 2.1 Разрабатывается | `в работе`, `возвращено из N` | работа идёт — или результат не прошёл проверку Выпускающего и вернулся | Разработчик; Выпускающий |
| 2.2 Проверяется Разработчиком | `у автора` | сделано и работает только в IWE Разработчика: на обкатке или в его версии файлов, опередившей шаблон | Разработчик |
| 2.3 Готово для передачи Выпускающему | `готово для передачи` | все записи результата влиты в основную ветку шаблона после последнего выпуска, у записей заполнены четыре поля (ниже; пометка «на разметке» заполнением не считается); отсюда Выпускающий берёт в выпуск | Разработчик; «влито» проверяет программа |
| 2.4 Взято Выпускающим | `взято в N`, `в rc N.K`, `готово к выпуску N` | отобрано в выпуск N → сборка на проверке → проверено, решено выпускать | Выпускающий; программа, по меткам сборок |
| **3. Сделано** | `сделано`, `выпущено в N`, `работает вне выпуска шаблона` | результат отмечен как сделанный, и в учёте выпуска нет незавершённого этапа 2.1–2.4 | исходный документ; программа по подтверждённым статусам |
| **4. Отложено** | `отложено`, `отложено в N` | Разработчик отложил работу — или Выпускающий не взял результат в выпуск N | Разработчик; Выпускающий |

**После выхода выпуска.** Сделанный результат, все связанные записи которого вошли в выпуск N, получает `выпущено в N` и переходит в «Сделано»; у вышедшего выпуска есть своя страница-список внутри «Сделано» (до выхода 0.42 результаты 0.37–0.41.11 стояли на этапе 2.3.1, адрес их страницы сохранён). Записи вышедшего выпуска Разработчик ведёт в разделе `released_0_42` файла [связей](../board/developer-links.yaml), а `links` держит только невыпущенные. Файл передачи с номером уже вышедшего выпуска программа не читает: его кандидаты и `releases/N/shipped.md` после выхода не меняются. Новая версия в списке изменений, для которой у программы нет диапазона, останавливает сборку.

**Поставлено вне шаблона: `работает вне выпуска шаблона`.** В исходном документе такой результат имеет стадию «сделано» и учитывается в пункте 3 общего табло. Его поставили через отдельный плагин, сервис или расширение. Список показывает канал пользователя и подтверждение места реализации; путь поставки не меняет общий счёт исходных стадий.

**Файлы Разработчика, отличающиеся от шаблона.** На странице стадии 2.2 есть отдельный список файлов, где версия в IWE Разработчика отличается от шаблона. Его даёт замер Разработчика (`author-ahead.yaml` среди источников сборки; программа замера — `wp529-drift-inventory.py --yaml-out` в DS-ai-systems). Файл — справка, а не единица счёта: он не переводит результат из стадии в стадию и в числа табло не входит. Каждый файл показан ровно один раз в одной из трёх групп: «уйдёт в шаблон при синхронизации» (в шаблоне своих правок нет), «расходится с шаблоном» (в шаблоне есть свои правки — версии сверяют вручную) и «не доказано» (принятая версия не прошла проверку перед доставкой — нужна проверка Разработчика). Кто ушёл вперёд — Разработчик, шаблон или оба, — замер не различает: этот признак зависит от памяти программы синхронизации на конкретном компьютере. Если замер сделан по другой версии шаблона, чем табло, страница это помечает. Связь файла с результатом ставит Разработчик в разделе `files:` файла `board/developer-links.yaml` теми же тремя видами (`result`, `proposed`, `service`); без связи файл стоит как «не привязано». Нет замера — страница так и пишет; неполный замер (тайм-аут, сбой, незнакомая строка журнала) показывается причиной, без списка файлов; повреждённый файл замера останавливает сборку.

**Заявленное и вычисленное.** Статусы, которые ставят роли, — заявленные. Статусы, которые ставит программа, она вычисляет по основной ветке и меткам шаблона, поэтому они всегда совпадают с шаблоном. Когда заявленное противоречит шаблону (правка уже влита, а результат ещё «в работе»; поля записи пусты, а статус «готово для передачи»), строка получает пометку **«расходится»**; у результатов, взятых в выпуск, такая пометка останавливает выпуск.

## Табло

Табло показывает сводный счёт всех результатов по четырём стадиям с учётом подтверждённых статусов подготовки выпуска. Раскрываемая таблица полностью распределяет пункт 2 по этапам 2.1–2.4. В сверке сохранены ссылки на коды этих групп и объяснена разница с исходными стадиями; описания результатов остаются в источнике. Изменение источников отразится в числах после получения нового снимка и пересборки.

**Какие результаты в списках подготовки выпуска.** Для этих отдельных списков программа берёт результаты целей, средство которых размещено в шаблоне IWE, на обкатке или в Open, все цели блока «Своя IWE» и цели Библиотеки методов. Это отбор по цели целиком: он может захватывать результаты других систем и не служит итогом общего табло. Статусы подготовки выпуска проверяются отдельно.

**Ничего не теряется.** При каждой сборке программа сверяет, что каждый код исходного документа учтён в сводном счёте ровно один раз, а материалы подготовки выпуска учтены в рабочих списках. Если числа не сошлись, сборка падает ([сверка полноты](../board/completeness.md)).

**Что пока неполно.** В «Состоянии по целям» есть только результаты открытых работ, поэтому результаты давно закрытых работ в сводный счёт ещё не попали. Записи выпусков 0.37–0.41.11 связаны с результатами предварительно, до приёмки Разработчиком; записи выпусков до 0.36 — следующая очередь.

## Пользовательский вид табло

В начале этой страницы — выбранные улучшения, понятные пользователю. Состояние каждой записи берётся из того же снимка, что и полное табло; ссылка ведёт к исходной строке. Дата состояний — дата снимка, дата текста — день редактирования описания. Наличие записи не обещает срок или состав следующего выпуска.

Разработчик выбирает записи в разделе `public_board` файла [связей](../board/developer-links.yaml): `schema_version: 1`, список `entries`, у каждой записи код `code`, признак показа `show`, понятное название `title` и дата текста `updated_at` строкой `YYYY-MM-DD`. Без `show: true` запись скрыта. Отдельного владельца результата этот вид не назначает; вопросы принимает команда выпуска.

| Группа | Условие показа |
|---|---|
| Вышло и доступно | Исходный статус «выпущено в 0.36», «выпущено в 0.37–0.41.11», «выпущено в 0.42» или «выпущено в 0.42.1»; размещение, стабильная версия и подтверждение выпуска согласованы со снимком (для «выпущено в 0.42» по записям выпуска — версия 0.42.0, для «выпущено в 0.42.1» — версия 0.42.1) |
| В работе | Исходный статус «в работе» или «возвращено из 0.42» |
| Рассматриваем | Исходный статус «план», явный отбор `vote_candidate: true` и публичная ссылка на решение `selection_url` |
| Приостановлено | «Отложено» либо приостановленная работа; заполнены причина `pause_reason` и ссылка на неё `pause_source_url` |

Результаты только у автора, готовые к передаче или взятые в 0.42 этот вид пока не показывает. Версия в размещении сама по себе не означает, что весь результат выпущен. Состав следующего выпуска и опрос о нём — на странице плана этого выпуска в папке `releases/`.

Пересобрать только этот вид (и каталог выпусков: `releases/INDEX.md`, `releases/HISTORY.md`, `releases/NEXT.md` и `releases/catalog.json`): `python3 tools/build_board.py --repo . --user-board-only`. Проверить соответствие без записи: `python3 tools/build_board.py --repo . --check-user-board` — эта проверка выполняется и в GitHub Actions; она же сверяет каталог выпусков. Ссылки всех страниц, кроме журналов проверок, проверяет `python3 tools/build_board.py --repo . --check-links`. Обычная полная сборка с `--src` обновляет его после успешной сверки полноты. Без раздела `public_board` полная сборка работает по-прежнему.

Страницу [NOW.md](../NOW.md) целиком создаёт программа; вручную её не правят. На ней три раздела. «Над чем идёт работа»: версия в проверке, версии в плане (из файла `releases/index.yaml`) и записи групп «В работе», «Рассматриваем», «Приостановлено». «Что вышло и доступно»: вышедшие версии и записи группы «Вышло и доступно». «Как читать состояния»: расшифровка состояний версий и строка счёта (из общего табло `board/README.md`). Ошибка в любой показанной записи останавливает обновление страницы; прежняя версия остаётся. Пустые группы допустимы, скрытие последней записи убирает старый текст.
