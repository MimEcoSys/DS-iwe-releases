Мы готовим выпуск шаблона IWE 0.43 и хотим знать, что вам нужнее всего. Ниже 8 вариантов. Варианты 1-7 уже сделаны, но в шаблон IWE ещё не переданы; вариант 8 для IWE пока проектируется. В каждом варианте сначала описана проблема, потом что будет сделано: какая система (запущенная программа или агент) будет действовать и какой документ (файл) появится. Выбрать можно любое число вариантов. Голоса помогают решить, что передать первым, но не заменяют проверку готовности: в выпуск попадает то, что прошло проверку.

Исправления безопасности по итогам проверки 0.42 выйдут в исправительном выпуске 0.42.1 при любом исходе голосования и здесь не перечислены.

## Варианты

### 1. План дня строится из плана недели

- **Проблема:** утренний план дня в шаблоне составляет языковая модель. Она иногда пропускает задачи, перенесённые со вчера, берёт часы не из плана недели и ставит пометку «срочно» без причины. День начинается с исправления плана.
- **Что будет сделано:** система - программа, которая после модели пересобирает таблицу задач дня из плана недели: задачи на сегодня и вчерашний перенос, часы и пометки берутся из плана недели. Если что-то не сходится, программа пишет об этом строкой в самом плане, а не молчит. Документ - план дня с этой таблицей.
- **Состояние:** сделано и используется каждый день; в шаблон ещё не передано.
- **Коды для сверки:** Ц34-02.

### 2. Видно часы по направлениям и близкие сроки

- **Проблема:** перекос недели обнаруживается только в её конце: непонятно, сколько времени уже ушло на каждое направление, а сроки из плана недели легко пропустить.
- **Что будет сделано:** система - программа, которая каждый вечер при закрытии дня считает часы, набранные по каждому направлению; при закрытии дня агент напоминает о ваших пометках о сроках из плана недели. Документ - файл «Состояние недели» с часами против плана.
- **Состояние:** сделано и используется; часы считаются, когда в плане недели указаны направления. В шаблон ещё не передано.
- **Коды для сверки:** Ц35-03, Ц35-04.

### 3. Самостоятельная проверка гипотез

- **Проблема:** итог проверки гипотезы готовит агент, и легко согласиться с ним, не проверив самому. Задача, ради которой ставилась гипотеза, продолжается, даже когда гипотеза опровергнута.
- **Что будет сделано:** документ - журнал гипотез, где каждая пятая гипотеза с уверенностью от 80 процентов помечена «сверить самому»: её вы проверяете, не видя вывода агента. Система - утренняя программа подбора задач, которая ставит на пересмотр задачу с опровергнутой гипотезой.
- **Состояние:** правило и программа сделаны, на деле пока не применялись. В шаблон ещё не передано.
- **Коды для сверки:** Ц38-07, Ц40-03.

### 4. Работу можно раздать нескольким ИИ-агентам

- **Проблема:** сейчас в шаблоне несколько ИИ-агентов могут только обсуждать одну задачу по очереди. Когда работы много или нужен независимый контроль, раздать её агентам нельзя.
- **Что будет сделано:** системы - четыре программы, каждая устраивает работу агентов по-своему: раздать независимые подзадачи сразу нескольким агентам; провести работу по цепочке, где каждый берёт результат предыдущего (черновик, критика, правка); поставить одного агента принимать или возвращать на доработку работу других; раздать поток мелких однотипных задач группе агентов. Документ - общий отчёт по итогам.
- **Состояние:** программы сделаны, применялись редко. В шаблон ещё не переданы.
- **Коды для сверки:** Ц82-07.

### 5. Базы знаний других авторов

- **Проблема:** агент ищет только по вашей базе знаний. Чтобы пользоваться методами другого автора, их приходится переносить вручную.
- **Что будет сделано:** документ - файл каталога доступных баз знаний. Система - агент IWE, который по вашей команде подключает базу другого автора к вашей среде только для чтения и включает её в поиск.
- **Состояние:** сделано и используется; в шаблон ещё не передано.
- **Коды для сверки:** S-58, S-62.

### 6. Разбор проекта

- **Проблема:** самому трудно увидеть, где проект слабее всего и с чего начать улучшение.
- **Что будет сделано:** система - агент IWE в роли проверяющего, который проходит проект по чек-листу. Документ - отчёт: уровень по каждому пункту с подтверждением и три главных пробела, у каждого сказано, что делать.
- **Состояние:** сделано и используется; в шаблон ещё не передано.
- **Коды для сверки:** S-72.

### 7. Забытые наработки находятся сами

- **Проблема:** правки, которые не сохранили в хранилище, и файлы, лежащие вне хранилищ, со временем теряются: о них забывают, и они не попадают ни в одну копию.
- **Что будет сделано:** система - программа, которая при закрытии недели ищет несохранённые правки и файлы вне хранилищ. Документ - отчёт закрытия недели с разделом найденного.
- **Состояние:** сделано и используется; в шаблон ещё не передано.
- **Коды для сверки:** S-52.

### 8. ИИ-наставник в чате IWE

- **Проблема:** когда непонятно, что происходит и что делать дальше, помощь нужна сразу, а не по расписанию. В IWE такого наставника нет.
- **Что будет сделано:** система - программа на платформе, которая делает разбор: вы описываете ситуацию своими словами и получаете разбор и рекомендацию, что делать и какой метод применить. Telegram-бот, агент IWE и чат в браузере обращаются к ней и показывают один и тот же ответ.
- **Состояние:** в Telegram-боте МИМ наставник работает, но разбор пока делает сам бот. Для IWE программу на платформе проектируют, она ещё не написана, срок не назначен. Голос за этот вариант показывает приоритет, а не обещает его в выпуске 0.43.
- **Коды для сверки:** Ц57-03, Ц57-06.

## Короткая версия для опроса

**Вопрос:** Что из этого вам нужнее всего в IWE? Выберите любое число вариантов.

1. План дня берёт задачи и часы прямо из плана недели, без пропусков и ошибок
2. Видно, сколько часов набрано по каждому направлению недели и какие сроки близко
3. Каждую пятую уверенную гипотезу я сверяю сам, не видя вывода агента
4. Можно раздать работу нескольким ИИ-агентам: одновременно, по цепочке или под проверкой
5. Можно подключить базу знаний другого автора и искать по ней вместе со своей
6. Агент разбирает мой проект и называет три главных пробела
7. Раз в неделю агент показывает несохранённые правки и файлы вне хранилища
8. ИИ-наставник в чате IWE: опишите ситуацию своими словами и получите разбор и следующий шаг

## Что не вынесено на голосование

- **Сбор выводов недели в постоянные записи** (Ц37-01) - работа не подтверждена: готовых недельных сводок с этим разделом нет.
- **Проверка названия новой задачи по реестру понятий** (Ц38-14) - в шаблоне её уже выполняет Артефактор, если установлен пак с реестром.
- **План дня без дублей на Linux** (Ц34-15) - исправление, а не новая возможность.
- **Запуски закрытия дня и недели в одной таблице** (Ц38-02), **ответы агента без внутреннего жаргона**, **закрытие сессии при нескольких агентах одновременно**, **чистка старых записей бесед** - касаются внутреннего устройства или их работа не подтверждена.
- **Починка недельного поста** ([Ц35-05](../../../board/at-developer.md)) - в шаблоне недельный пост устроен иначе, переносить нечего.
- **Персональное руководство без повторов темы** ([обращение #836](https://github.com/TserenTserenov/FMT-exocortex-template/issues/836)) - руководство собирает сервер платформы, исправление выходит вне выпусков шаблона.
- **Запись памяти агента без подтверждений** ([обращение #1487](https://github.com/TserenTserenov/FMT-exocortex-template/issues/1487)) - входит в 0.42.1 (решение Выпускающего 18.11.2026).
- **Утренний план по подписке Claude** ([обращение #1478](https://github.com/TserenTserenov/FMT-exocortex-template/issues/1478)) и **место для учебных конспектов** ([обращение #1473](https://github.com/TserenTserenov/FMT-exocortex-template/issues/1473)) - остаются обращениями.

## Как проходит опрос

Один опрос в Telegram, 8 вариантов (предел Telegram - 12 вариантов по 100 символов, вопрос до 300; источник: [документация Bot API, метод sendPoll](https://core.telegram.org/bots/api#sendpoll), сверено 2026-11-17). Выбрать можно любое число вариантов. Ссылку на эту страницу ставят в запись над опросом: в вопросе опроса Telegram ссылка не кликается (проверено 18.11.2026). Опрос идёт три дня, до 21.11.2026; в Telegram он сам по сроку не закрывается, его останавливают вручную. Итоги публикуются на этой странице и в списке будущих выпусков ([NEXT.md](../../NEXT.md)); состав 0.43 называет Выпускающий с учётом голосов.
