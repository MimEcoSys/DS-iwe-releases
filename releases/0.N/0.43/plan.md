# Выпуск 0.43 — план

> **Состав утвердил Выпускающий 21.11.2026** по итогам [голосования](vote.md). Срок не назначен: выпуск 0.43 собирается после выхода исправительного выпуска [0.42.2](../0.42.2/README.md). Черновик Разработчика от 18.11.2026 заменён этой версией.

## Правило: исправления и новое - в разные выпуски

- **0.42.2** - только исправления ошибок и долг проверок (решение Выпускающего 21.11.2026).
- **0.43** - новые возможности по итогам голосования.

Программа выпуска шаблона (`release.yml`) выпускает только коммит основной ветки, и дерево этого коммита должно совпасть с деревом проверенной сборки-кандидата. Поэтому выпуски идут по очереди:

1. Сейчас в основную ветку шаблона вливаются только исправления. Новое для 0.43 готовится в отдельных ветках и запросах на слияние, но не вливается.
2. Выходит 0.42.2.
3. После этого в основную ветку вливается новое для 0.43, и собирается кандидат 0.43.

Если до выхода 0.42.2 в основную ветку всё же что-то вольют, кандидат 0.42.2 собирается и проверяется заново.

Выпускать исправления параллельно с новым (ветка сопровождения от метки прошлого выпуска) нынешняя программа выпуска не умеет. Это отдельная доработка конвейера, она есть в списке работ Выпускающего.

## Долг конвейера выпуска (цель: 0.43 собирается без ручной доводки)

Источник - разбор итогов 0.42; порядок не определён.

1. Номера версий не вписывать руками в программы и описания (сначала решить, откуда программа берёт текущую версию).
2. Одна программа собирает входные данные выпуска (состав, журнал, табло).
3. Перевод: проверка «нет кириллицы» по всему английскому дереву на каждом запросе на слияние, а не только на основной ветке.
4. Журнал изменений без конфликтов между параллельными запросами.
5. Срочная рассылка о безопасности: живая проверка доставки как шаг выпуска.
6. Проверка на macOS программой выпуска до раздачи людям: по итогам 0.42 именно переход с 0.36 и macOS дали две пересборки (rc.10 и rc.11), см. [итог 0.42](../0.42/retro.md).
7. Сборка рабочей среды автора не должна перезаписывать корневые файлы-источники.
8. Проверка объёма горячих инструкций (`verify-context-budget.sh`) красная: 21,5K при пределе 20K.
