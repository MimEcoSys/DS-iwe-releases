## Как готовилась установка

Для каждой проверки — новая пустая папка, свежий клон ветки с GitHub и `SETUP_CI=1 bash setup.sh --core` с временной домашней папкой, чтобы установка не писала в настройки оболочки автора (контрольные суммы `~/.zshenv` и `~/.bashrc` до и после совпали). Режим `--core` не ставит фоновых задач. Клон и установку делал Разработчик; проверочные шаги выполнял Hermes.

## Что пошло не так по дороге

- Отчёт Hermes из вкладки редактора 27.11 утром не принят: проверки не запускались, отчёт составлен по критериям поручения (нераскрытый путь временной папки, несуществующие файлы, числа-заглушки).
- Первый прогон с журналом: Hermes подал шаги разом, переменная с путём к программе не дошла до шага запуска (`exit=127`), раздача не выполнялась; терминал Hermes унаследовал пути автора из окружения редактора.
- Второй прогон: раздача прошла (журнал выше); подключение пака сорвалось — Hermes ограничил каждый шаг минутой, разговоры Claude оборвались, а путь «названного файла» он записал до ответа агента. Третий прогон — одной программой — прошёл.

## Замечания к черновикам

- При запуске `claude -p` в новой папке Claude Code пишет «Ignoring 34 permissions.allow entries … workspace has not been trusted»: в беседе без окна папка не отмечена доверенной. В VS Code человек подтверждает доверие при первом открытии; на итог проверки не повлияло.
- Хук закрытия сессии в беседе без окна пишет «SessionEnd hook … failed: Hook cancelled» — шум беседы без окна, на итог не повлиял.
- Хук зеркала памяти (`memory-exocortex-sync.sh`) берёт имя репозитория управления сначала из переменной `GOVERNANCE_REPO`, а уже потом из `IWE_GOVERNANCE_REPO` установки. На машине автора эта переменная задана редактором, поэтому в чистой установке появилась папка с именем репозитория автора. У нового пользователя переменной нет; в репозиторий автора ничего не ушло. Кандидат в бэклог 0.44.
