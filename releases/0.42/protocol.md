# Выпуск 0.42 — протокол проверки сборки

Подготовил Разработчик (WP-529). Что из строк блокирует выпуск, решает Выпускающий в [decisions.md](decisions.md); колонка «Блокирует» ниже — предложение Разработчика.

Сборка-кандидат — метка шаблона `v0.42.0-rc.<K>` на ветке `release/v0.42.0`. Новая сборка (`rc.2`, `rc.3`…) — все строки заново: отметки прошлой сборки не переносятся. Отметки — в [tests/](tests/README.md), один файл на сборку.

## Порядок

1. **Программы.** Перед раздачей сборки тестировщикам — обе проверки без замечаний:
   `python3 ops/check_decisions.py` (здесь) и `python3 scripts/check-changelog-fields.py --ref v0.42.0-rc.<K> --section 0.42.0` (в шаблоне). Без полей у записей сборка вообще не ставится.
2. **Рецензия.** Рецензент выпуска (ИИ-агент) судит поверх вывода обеих программ, со ссылкой «файл:строка» на каждое замечание. Решения он не принимает.
3. **Проверка сборки** — строки 1–12 и 14–18 ниже, тестировщики и Разработчик.
4. **Независимая атака (red team)** — строка 13, по методу Евгения Селивёрстова (скилл шаблона `iwe-platform-redteam`). Проверяющий — не автор кода выпуска: агент в отдельной беседе без контекста разработки или человек. Вердикт до слияния — **вне дерева ветки выпуска**: комментарием в запросе на слияние ветки выпуска и блоком `red_team` в [tests/rc.<K>.yaml](tests/README.md) (вердикт, кто проверял, ссылка на отчёт, дерево кандидата). Журнал шаблона `docs/release-audit-log.md` лежит внутри ветки выпуска: запись туда после метки кандидата меняет дерево, и программа выпуска остановит выпуск. Поэтому в журнал вердикт попадает отдельным запросом после выхода. Вердикт относится к одному кандидату: новая сборка — новая атака.
5. **Находка.** Исправление — на ветке выпуска, затем новая сборка и повтор с шага 1. Либо Выпускающий явно принимает оговорку — она идёт в анонс. Иначе находка остаётся открытой, и строка не пройдена.
6. **Слияние.** Выпускающий сливает ветку выпуска, только когда все блокирующие строки пройдены. Прямо перед слиянием — две проверки: в шаблоне `bash scripts/check-release-branch-base.sh 0.42.0` (основная ветка не сдвинулась после нарезки; если сдвинулась — влить её в ветку выпуска и заново пройти сборку, порядок в `docs/RELEASE-PROCESS.md`) и здесь `python3 ops/check_decisions.py --require-final --rc-tree <дерево из комментария последней сборки>` (форма решений заполнена до строки «Итог», у последней сборки записан вердикт атаки для этого дерева). Программа выпуска опубликует 0.42.0, только если выпускаемое совпадает с последней сборкой-кандидатом.

**Честная оговорка о независимости.** Пока Разработчик, Выпускающий и проверяющий атаку — один человек, обязательность этих проверок держится только на программах выше, а не на независимости ролей. Кто что исполняет, записывается в decisions.md, строка «Кто исполняет роли».
7. **После выхода** — проверка опубликованного выпуска (напоминание шаблона создаётся само для `x.y.0`) и окно наблюдения из decisions.md.

## Известная оговорка

**Задача #1124: защитные проверки репетиции не срабатывают в Кими.** Кими не исполняет проверки из настроек Claude Code, поэтому «сухой» прогон ритуала из Кими может по-настоящему записать файлы. Исправление есть только в виде замысла и затрагивает четыре места записи — в 0.42 его нет. Предложение Разработчика: оговорка в анонсе «репетиции ритуалов запускать только из Claude Code». Решает Выпускающий.

## Для тестировщика с Windows

Нужно 20–30 минут, Windows с установленным IWE и Git Bash. Ничего не нужно понимать в устройстве IWE: достаточно скопировать команды и прислать вывод.

**Перед началом.** В Git Bash выполните `command -v jq || echo "jq нет"`. Хук защиты и скрипт завершения репетиции разбирают вход через `jq`, а в Git Bash его по умолчанию нет: без `jq` хук отвечает кодом 2 на любой вход (запись «заблокирована» по неверной причине), а чтение в пункте 3 не проходит. Если выведено «jq нет» — поставьте его (`winget install jqlang.jq`, затем откройте Git Bash заново) или сообщите об этом в комментарии вместо вывода пунктов 3–4.

1. **Копия.** Скопируйте всю папку IWE рядом (например, `IWE-backup`). Если что-то пойдёт не так — удалите папку IWE и переименуйте копию обратно.
2. **Поставить сборку.** В Git Bash:
   ```bash
   cd ~/IWE/FMT-exocortex-template
   IWE_UPDATE_CHANNEL=rc bash update.sh
   ```
   В выводе должна быть строка `Канал поставки: кандидат v0.42.0-rc.…`. Сохраните последние 20 строк вывода.
3. **Проверка защиты.** Там же, в Git Bash:
   ```bash
   cd ~/IWE/FMT-exocortex-template
   # Агент исполняет хук из ~/IWE/.claude/hooks, а не из папки шаблона: проверяем тот, что исполняется.
   HOOK="$HOME/IWE/.claude/hooks/dry-run-gate.sh"; [ -f "$HOOK" ] && echo "хук: $HOOK" || echo "ХУК НЕ НАЙДЕН: $HOOK — установка не в ~/IWE; укажите её путь в HOOK=... и не продолжайте с этим значением"
   bash scripts/dry-run-begin.sh audit-installation windows-test hold; echo "начало: $?"
   echo '{"tool_name":"mcp__aisystant__personal_write","tool_input":{}}' | bash "$HOOK"; echo "запись aisystant: $?"
   echo '{"tool_name":"mcp__aisystant__personal_search","tool_input":{}}' | bash "$HOOK"; echo "чтение aisystant: $?"
   ```
   Ожидается: `начало: 0`, `запись aisystant: 2`, `чтение aisystant: 0`. Скрипт начала печатает три строки `gate_id=`, `owner_token=`, `owner_session_id=` — они нужны для пункта 4.
4. **Завершить репетицию** (подставьте три значения из пункта 3):
   ```bash
   bash scripts/dry-run-complete.sh "<gate_id>" rehearsal-finished "<owner_session_id>" "<owner_token>"; echo "конец: $?"
   echo '{"tool_name":"Write","tool_input":{"file_path":"x"}}' | bash "$HOOK"; echo "вне репетиции: $?"
   ```
   Ожидается: `конец: 0`, `вне репетиции: 0` (вне репетиции агент не заблокирован).
5. **Если работаете в Claude Code** — вместо пунктов 3–4 можно сказать агенту `/audit-installation` и прислать раздел 6 его отчёта.
6. **Прислать результат** комментарием в задачу [#1447](https://github.com/TserenTserenov/FMT-exocortex-template/issues/1447): версия Windows, вывод пунктов 2–4 (или раздел 6 отчёта). Если где-то ошибка — текст ошибки целиком. Личных путей и имени пользователя Windows в выводе можно не скрывать — но если хотите, замените их на `…`.
7. **Вернуться на обычную версию** — после выхода 0.42.0 просто `bash update.sh`; сразу — удалить папку IWE и вернуть копию.

Отметку в `tests/rc.<K>.yaml` по присланному результату ставит Разработчик, со ссылкой на комментарий.
