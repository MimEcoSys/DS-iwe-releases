# Выпуск 0.42 — с чего начать Выпускающему

Подготовил Разработчик. Здесь всё, что нужно для решения по 0.42; решает Выпускающий.

## Что читать по порядку

1. **[Кандидаты](candidates.md)** — правки, влитые в шаблон после 0.41.11. У каждой: что получит пользователь, как проверить, как откатить, риск и рекомендация Разработчика «взять / отложить / решить Выпускающему». Там же — группы правок из одного слияния: неразделимую группу берут или откладывают целиком.
2. **Что люди уже получили после 0.36** — [результаты](../../board/2.3.1-released-0.37-0.41.11.md) и [все записи выпусков 0.37–0.41.11](../0.41.11/shipped.md). Тот, кто стоит на 0.36, при переходе на 0.42 получит и это, и всё, что взято из кандидатов. По данным Разработчика на 04.11, на 0.36 стояли 4 из 15 пользователей.
3. **[Решения](decisions.md)** — форма, которую заполняет Выпускающий.

## Как отложить уже влитое

Все кандидаты уже в основной ветке шаблона. Ветка выпуска делается от основной ветки в момент «режем», поэтому отложить кандидата — значит снять его откатом на ветке выпуска. Делать это нужно до метки сборки-кандидата. Между меткой кандидата и слиянием ветки выпуска основную ветку не двигают: иначе выпускаемое разойдётся с проверенным кандидатом, и выпуск остановится. Ветка выпуска потом вливается в основную ветку, поэтому отложенное исчезнет и оттуда, а вернуть его в следующий выпуск можно, откатив сам откат. Порядок отката и что делать с конфликтами — на [странице кандидатов](candidates.md#как-откатывать).

## Что ждёт решения Выпускающего

1. Состав: что из кандидатов взять, что отложить.
2. Предел числа правок в выпуске — чтобы проверка сборки не растянулась на недели.
3. Какие строки проверки сборки блокируют выпуск.
4. Обещает ли 0.42 работу в Windows. Исправления для Windows уже среди кандидатов; если обещает, нужна отдельная проверка на Windows.
5. Кто проверяет сборку (тестировщики).
6. Сколько наблюдать после выхода и какие обращения пользователей считать поводом для отката.
7. Нужны ли записям-документации поля «как проверить» и «как откатить» или им достаточно цели.

## Чего не хватает в механике выпуска

Проверено 05.11 по основной ветке шаблона. Это работа Разработчика, не решение Выпускающего, но без неё 0.42 выпустить нечем:

- **У Выпускающего нет прав в самом шаблоне.** Шаблон принадлежит личному аккаунту Разработчика, а команда Выпускающего в организации MimEcoSys даёт доступ только к этому репозиторию. Без прав на запись в шаблон нельзя сделать ветку выпуска, откаты и сборку. Нужно либо дать Выпускающему права соавтора в шаблоне, либо перенести шаблон в организацию.
- **Сборку-кандидат сейчас поставить нечем.** Метку кандидата ставит только недельный выпуск: он делает ветку выпуска, сразу ставит метку и открывает запрос на слияние в основную ветку. Этот выпуск выключен вручную. Если включить его, вернётся и воскресное расписание, поэтому нужен ручной запуск без расписания.
- **Выпуск без кандидата не останавливается.** Программа выпуска в этом случае только предупреждает. Если выпускаемое не совпадает с последним кандидатом, она выпуск останавливает.
- **Переход с 0.36 на кандидат не проверен.** Обновление в 0.36 само каналов не знает, но перед работой скачивает свежую версию себя, а та их знает. Поэтому команда `IWE_UPDATE_CHANNEL=rc bash update.sh`, скорее всего, поставит кандидата и на 0.36. Это нужно проверить на копии установки 0.36. Проверка без установки (`--check`) себя не обновляет и кандидата с 0.36 не увидит.
- **Выбрать версию командой обновления нельзя.** Вернуть пользователей назад может только издатель: снова сделать прежний выпуск последним, тогда обновление предложит откат. Путь 0.42 → 0.41.11 нужно проверить до выпуска. Для отдельного пользователя путь назад — копия всего каталога установки, сделанная до обновления.
- **Описание порядка выпуска в шаблоне устарело.** Там описан отменённый недельный выпуск и неверное время запуска: 20:00 UTC вместо 17:00 UTC.
- **Скилл обновления читает список изменений с основной ветки, а не с выпуска или кандидата.** Тестировщику кандидата он объяснит изменения не по тому источнику.

## Что нужно от Выпускающего сразу

Логин GitHub. По нему Выпускающего добавят в команду организации MimEcoSys и дадут права в шаблоне. Пока в команде только владелец репозитория.

## Словарь

| Слово | Что значит |
|---|---|
| сборка-кандидат (rc) | проверяемая сборка будущего выпуска; выходит ровно та, что прошла проверку |
| ветка выпуска | ветка шаблона, на которой собирают выпуск; делается от основной ветки в момент «режем» |
| слияние | влитый в основную ветку запрос на слияние (PR, номер `#NNNN`) |
| откат | коммит, который снимает изменения другого коммита (`git revert`) |
| репетиция, пробный прогон | режим проверки установки, в котором агенту запрещено что-либо записывать; одно и то же |
| защита, хук, гейт | программа, которая проверяет каждое действие ИИ-агента и может его запретить |
| разборщик | фоновая роль шаблона, которая разбирает заметки и извлекает из них знания |
| Кими | второй ИИ-агент, с которым может работать среда IWE |
| РП | рабочий продукт — единица работы Разработчика |
| «Ц84-04» | код обещанного результата: цель 84, результат 04 |
| «новый результат цели 70» | правка служит цели 70, но результата для неё в «Состоянии по целям» ещё нет |
| «служебное» | у правки нет видимого пользователю результата |
