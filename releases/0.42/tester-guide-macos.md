# Выпуск 0.42 — инструкция тестировщику на macOS

> **Статус: черновик.** Разработчик проходит эти шаги сам на первом кандидате (`rc.1`) до передачи и исправляет то, что не совпадёт с экраном. До этой отметки по инструкции не работать: _прогон Разработчика — не сделан_.

Ты проверяешь сборку-кандидат шаблона IWE до того, как её получат все пользователи, и пробуешь её сломать. Твой отчёт решает, выходит ли 0.42. Ты не автор этого кода, поэтому твой взгляд и нужен.

**Время:** 3–4 часа, можно в два захода. **Что понадобится:** Мак, VS Code, аккаунт GitHub, доступ к Claude (даст Выпускающий). **Что получишь от Выпускающего:** номер кандидата (например, `rc.1`) и ссылку на тему «Выпуск 0.42» в Зулипе.

Твои строки протокола: **1, 2, 4, 5, 10, 13, 18**, и по желанию **17** (если есть ChatGPT). Остальные строки делают другие.

## Правила безопасности

1. **Всё делай в отдельной учётной записи Мака**, не в своей. Так тест не тронет твои файлы, а после проверки учётную запись можно просто удалить.
2. Установка IWE создаст в твоём GitHub приватный репозиторий `DS-strategy` и поставит фоновые задачи в этой учётной записи. После проверки репозиторий можно удалить; фоновые задачи удалятся вместе с учётной записью.
3. Если шаг не совпадает с тем, что написано, — **остановись**, сделай снимок экрана и напиши в тему «Выпуск 0.42». Не чини сам: найденное несовпадение — тоже результат.
4. Никаких паролей и ключей в отчёт, в Зулип и в снимки экрана.

## Шаг 0. Подготовка (один раз, 30–40 мин)

1. **Новая учётная запись:** «Системные настройки» → «Пользователи и группы» → «Добавить пользователя», имя `iwe-test`, тип «Администратор». Выйди из своей записи и войди в `iwe-test`.
2. **Терминал:** Cmd+Пробел → «Терминал».
3. **Программы** — по очереди, каждую строку отдельно:
   ```bash
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   brew install git node gh jq python
   npm install -g @anthropic-ai/claude-code
   gh auth login        # GitHub.com → HTTPS → Login with a web browser
   ```
4. **VS Code:** скачай с code.visualstudio.com, открой, Cmd+Shift+X → найди «Claude Code» → Install. Войди в Claude тем доступом, что дал Выпускающий.
5. **Номер кандидата** запиши в переменную, чтобы дальше копировать команды как есть (вместо `1` — номер от Выпускающего):
   ```bash
   echo 'export RC=v0.42.0-rc.1' >> ~/.zshrc && source ~/.zshrc
   ```

## Шаг 1. Установка 0.41.11 — основа для строк 2, 4, 10 (15 мин)

```bash
mkdir -p ~/IWE && cd ~/IWE
git clone --branch v0.41.11 https://github.com/TserenTserenov/FMT-exocortex-template.git
cd FMT-exocortex-template
bash setup.sh
```

На вопросы установки: логин GitHub — свой; остальное — Enter.

Сделай две «свои правки», чтобы потом проверить, что обновление их не стёрло:

```bash
echo "# моя правка для проверки" >> ~/IWE/extensions/test-marker.md
echo "test_marker: keep-me" >> ~/IWE/params.yaml
```

Сделай копию всей установки — это твой путь назад:

```bash
cp -R ~/IWE ~/IWE-0.41.11-copy
cp -R ~/.claude ~/.claude-0.41.11-copy
```

## Шаг 2. Строка 2 — обновление 0.41.11 → кандидат

```bash
cd ~/IWE/FMT-exocortex-template

```

**Пройдено, если:**
- в выводе есть строка `Канал поставки: кандидат v0.42.0-rc.<номер>`;
- обновление дошло до конца без ошибки;
- `cat ~/IWE/extensions/test-marker.md` и `grep test_marker ~/IWE/params.yaml` показывают твои правки;
- повторный запуск той же команды ничего не меняет.

## Шаг 9. Строка 13 — red team (1–1,5 ч)

Ты пробуешь сломать кандидата так, как это сделал бы злоумышленник или неудачное обновление. Делает это агент по готовому методу, ты запускаешь и следишь.

1. В VS Code открой папку `~/IWE/FMT-exocortex-template` (это кандидат из шага 7). Открой **новую** беседу Claude Code — без истории прошлых шагов. Модель — самая сильная из доступных.
2. Напиши:
   ```
   /iwe-platform-redteam проверь кандидат выпуска $RC: чистая установка, обновление с 0.41.11, возврат, права агента, защитные проверки. Только одноразовые копии во временной папке.
   ```
   (вместо `$RC` — номер, например `v0.42.0-rc.1`)
3. Агент сначала проверит себя на двух учебных сборках: заведомо плохую обязан заблокировать, заведомо хорошую — пропустить. Если это не вышло, он скажет `cannot_verify`. Это тоже результат: впиши его в отчёт как есть.
4. Если агент просит разрешения на команду, разрешай только то, что работает во временной папке (путь начинается с `/var/folders` или `/tmp`). Всё, что трогает `~/IWE` или `~/.claude`, — отклоняй.
5. В конце будет раздел `## Verdict` с одним словом: `GO`, `CAUTION` или `BLOCKED`. Попроси агента сохранить весь отчёт в файл `~/redteam-report.md`.
6. Узнай дерево кандидата — это подпись того, что ты проверял именно его:
   ```bash
   git -C ~/IWE/FMT-exocortex-template rev-parse "$RC^{tree}"
   ```

Заполни и отправь. Если ты в команде `iwe-testers` организации MimEcoSys — запросом на слияние в файл `releases/0.42/tests/rc.<номер>.yaml` этого репозитория; если нет — файлом Выпускающему, и Разработчик перенесёт его без правок.

```yaml

marks:
  - {line: 1,  result: пройдено, tester: <твой логин GitHub>, note: ""}
  - {line: 2,  result: пройдено, tester: <логин>, note: ""}
  - {line: 4,  result: пройдено, tester: <логин>, note: ""}
  - {line: 5,  result: пройдено, tester: <логин>, note: ""}
  - {line: 10, result: пройдено, tester: <логин>, note: ""}
  - {line: 18, result: пройдено, tester: <логин>, note: ""}
  # result: пройдено | не пройдено | не проверялось; в note — что увидел, без имён и личных данных

  verdict: GO                    # GO | CAUTION | BLOCKED | cannot_verify — слово из раздела Verdict
  checker: <твой логин GitHub>
  report: <ссылка на файл отчёта или на комментарий в запросе на слияние>
  tree: <40 символов из шага 9.6>
```

Отчёт red team (`~/redteam-report.md`) приложи целиком. Перед отправкой открой его и убедись, что там нет паролей, ключей и путей с твоим настоящим именем пользователя.
