# Отметки проверки

Здесь — всё, чем проверяли кандидатов выпуска 0.42: отметки, отчёты атаки, журналы и проверочные скрипты. Описание выпуска для пользователей сюда не входит — оно в шаблоне (`docs/releases/0.42/`).

## Раскладка

Одна папка на кандидата: `rc.<K>/`, например `rc.4/`. Новый кандидат — новая папка; отметки прошлого кандидата не переносятся.

```
rc.<K>/
  <платформа>-<логин>.yaml   — отметки одного тестировщика на одной платформе (linux-tsekh-1-agent.yaml, macos-<логин>.yaml)
  redteam-<платформа>.md     — полный отчёт независимой атаки (строка 13), если она была
  logs/<платформа>/          — журналы установки, обновления, ответы агента; без личных данных
  probes/                    — проверочные скрипты, которыми получены отметки
```

Платформа — `macos`, `linux` или `windows`. Логин — GitHub; для агента без логина — имя машины и `-agent` (`tsekh-1-agent`).

## Формат файла отметок

```yaml
build: 0.42-rc.4
marks:
  - line: 1                 # номер строки протокола releases/0.42/protocol.md
    result: пройдено        # пройдено | не пройдено | не проверялось
    tester: <логин GitHub>
    note: ""                # пересказ без имён и личных данных
red_team:                   # вердикт независимой атаки (строка 13) на ЭТОМ кандидате; нет атаки — блока нет
  verdict: GO               # GO | CAUTION | BLOCKED — слова навыка iwe-platform-redteam; cannot_verify = не пройдено
  checker: <кто проверял>   # не автор кода выпуска
  report: redteam-linux.md  # отчёт рядом в этой папке или ссылка на комментарий в запросе на слияние
  tree: <полный SHA дерева кандидата, из комментария next-rc>
  accepted_by: <логин>      # обязателен при CAUTION: оговорки принял Выпускающий
```

Программа `ops/check_decisions.py --require-final` смотрит последнюю папку `rc.<K>/` (по числу K) и проверяет каждый блок `red_team` в ней: если атаку провели двое, проходить должны оба вердикта.

Вердикт лежит здесь, а не в журнале шаблона: журнал внутри ветки выпуска, запись в него после метки кандидата меняет дерево и останавливает выпуск. В журнал — отдельным запросом после выхода.

## Перед публикацией

Хранилище открытое. Журналы и отчёты — без паролей, ключей, почты, телефонов и путей с настоящим именем пользователя; путь к ключу в скрипте заменяется переменной. Проверка при запросе на слияние: поиск секретов и `python3 ops/pii_scan.py`.
