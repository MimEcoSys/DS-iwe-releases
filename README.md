# DS-iwe-releases

Здесь команда выпуска шаблона IWE ведёт табло: где сейчас каждый обещанный результат шаблона — в плане, в работе, у Разработчика, у Выпускающего или уже у пользователей. Код шаблона — в [FMT-exocortex-template](https://github.com/TserenTserenov/FMT-exocortex-template); здесь решают, что и когда из него уходит пользователям.

## Табло с текущими цифрами

**[now/board.md](now/board.md)** — табло, только цифры; каждое число ведёт к списку результатов. Что вошло в выпуски: [до 0.36](releases/0.36/shipped.md), [0.37–0.41.11](releases/0.41.11/shipped.md).

**Как обновляется.** Сейчас — по запуску: Разработчик запускает программу `tools/build_board.py`, она заново читает шаблон и файлы ролей и пересобирает `now/` целиком. В первой строке каждого файла — дата сборки и версия шаблона, по которой он собран. Следующий шаг — сборщик в GitHub Actions: пересборка раз в час и при каждой правке, при сбое — автоматическая задача, а старый вид остаётся со своей датой (ещё не сделан).

Через выпуск идут три части: шаблон IWE, Open (туда попадает проверенное в IWE, и только после выпуска) и подключение Библиотеки методов.

## Роли

| Роль | Кто | Что делает здесь |
|---|---|---|
| Разработчик | `TserenTserenov` и его ИИ-агент | доводит результаты до готовности и передаёт их Выпускающему (ниже) |
| Выпускающий | назначен, логин уточняется | решает, что и когда выходит пользователям |
| Тестировщики | назначает Выпускающий | проверяют сборку и отмечают результат |
| Владелец репозитория | `TserenTserenov` | права доступа, состав команд |

Людей указываем только логином GitHub; все участники — члены организации MimEcoSys.

## Единицы счёта

| Единица | Что это | Откуда |
|---|---|---|
| **Цель** | чего хочет человек и по чему видно, что цель достигнута | [«Цели и сценарии»](https://github.com/MimEcoSys/PACK-digital-platform/blob/main/pack/digital-platform/07-map/DP.MAP.005-mcp-scenarios.md) |
| **Обещанный результат** | конкретная вещь, которую работа обещает человеку под одну цель; постоянный код «Ц<цель>-<номер>» | «Состояние по целям» (закрытый репозиторий; код и короткий текст перенесены в файл Разработчика снимком) |
| **Запись списка изменений** | строка `CHANGELOG.md` шаблона об одной правке | список изменений шаблона |
| **Запись обкатки** | строка `STAGING.md` Разработчика о поведении, которое он проверяет на себе | `STAGING.md` (закрытый репозиторий) |
| **Выпуск** | версия шаблона, которую получают пользователи: 0.36.3, 0.41.11, 0.42 | метки выпусков шаблона |

**Табло считает только обещанные результаты.** Записи — для справки: результат продвигается по стадиям, когда в шаблон, в отбор или в выпуск вошли все его записи. Запись, ещё не связанная с результатом, видна отдельно и в счёт не идёт.

## Стадии и статусы

**Стадия** — крупный этап результата, как в «Состоянии по целям»: план, в работе, сделано, отложено. **Статус** — где именно внутри стадии стоит результат; одно значение из закрытого списка ниже. Новый статус появляется только правкой этого раздела.

| Стадия | Статусы | Что значит | Кто ставит |
|---|---|---|---|
| **1. План** | `план` | результат обещан, работа не начата | Разработчик |
| **2. В работе** | | сумма 2.1–2.4 | |
| 2.1 Разрабатывается | `в работе`, `возвращено из N` | работа идёт — или результат не прошёл проверку Выпускающего и вернулся | Разработчик; Выпускающий |
| 2.2 Проверяется Разработчиком | `у автора` | сделано и работает только в IWE Разработчика: на обкатке или в его версии файлов, опередившей шаблон | Разработчик |
| 2.3 Готово для передачи Выпускающему | | сумма 2.3.1 и 2.3.2; отсюда Выпускающий берёт в выпуск | |
| 2.3.1 Вышло в 0.37–0.41.11 | `в разнице 0.36–0.41.11` | уже вышло пользователям после стабильного 0.36; Выпускающий решает, что из этого принять в 0.42 (пункт временный, до выхода 0.42) | программа, по выпускам шаблона |
| 2.3.2 Влито после 0.41.11 | `готово для передачи` | все записи результата влиты в основную ветку шаблона, у записей заполнены четыре поля (ниже) | Разработчик; «влито» проверяет программа |
| 2.4 Взято Выпускающим | `взято в N`, `в rc N.K`, `готово к выпуску N` | отобрано в выпуск N → сборка на проверке → проверено, решено выпускать | Выпускающий; программа, по меткам сборок |
| **3. Сделано** | `выпущено в N` | вышло пользователям в стабильном выпуске (сейчас — 0.36) | программа |
| **4. Отложено** | `отложено`, `отложено в N` | Разработчик отложил работу — или Выпускающий не взял результат в выпуск N | Разработчик; Выпускающий |

**Вне стадий: `работает вне выпуска шаблона`.** Результат той же цели сделан не в шаблоне, а в сервисе платформы — на сайте, в боте, в MCP-сервере. Через выпуск шаблона он не проходит, поэтому в итог табло («Итого по IWE» — сумма стадий 1–4) не входит; на табло он стоит отдельным списком.

**Заявленное и вычисленное.** Статусы, которые ставят роли, — заявленные. Статусы, которые ставит программа, она вычисляет по основной ветке и меткам шаблона, поэтому они всегда совпадают с шаблоном. Когда заявленное противоречит шаблону (правка уже влита, а результат ещё «в работе»; поля записи пусты, а статус «готово для передачи»), строка получает пометку **«расходится»**; у результатов, взятых в выпуск, такая пометка останавливает выпуск.

## Табло

Табло показывает результаты по стадиям и статусам выше: сколько результатов в каждой стадии и какие именно, с разбивкой по трём частям выпуска.

**Какие результаты на табло** — результаты целей, средство которых размещено в шаблоне IWE, на обкатке или в Open, все цели блока «Своя IWE» и цели Библиотеки методов. Список отбирает программа, а не человек.

**Ничего не теряется.** При каждой сборке программа сверяет, что каждый результат и каждая запись из источников есть на табло; если числа не сошлись, сборка падает ([сверка полноты](now/completeness.md)).

**Что пока неполно.** В «Состоянии по целям» есть только результаты открытых работ, поэтому результаты давно закрытых работ на табло ещё не попали. Записи выпусков 0.37–0.41.11 связаны с результатами предварительно, до приёмки Разработчиком; записи выпусков до 0.36 — следующая очередь.

## Как работаем

### Разработчик → Выпускающему

**Берёт:** обещанные результаты — из карточек своих работ и «Состояния по целям»; правки — из основной ветки и списка изменений шаблона; то, что проверяет на себе, — из своего `STAGING.md`.

**Делает:**
1. Доводит результат до готовности и вливает правки в основную ветку шаблона.
2. В каждой записи списка изменений заполняет четыре поля: цель, как проверить, как откатить, код результата. Поля проверяет программа шаблона (`changelog-gate.yml`), а не человек.
3. В своих файлах ставит статус результата (`roles/developer.yaml`) и связывает каждую запись с кодом результата (`roles/developer-links.yaml`).
4. Пересобирает табло.

**Отдаёт:** статус `готово для передачи` — результат появляется в строке 2.3 табло, и Выпускающий его видит. Для 0.42 Разработчик дописывает четыре поля во все накопленные записи до первой сборки.

### Выпускающий

Берёт из строки 2.3 то, что пойдёт в выпуск, и **сам строит свой процесс**: как отбирает и сколько берёт, как проверяют сборку, когда выпускать и когда откатывать. Решения записывает в `roles/release-lead.yaml` и `releases/<N>/decisions.md`. В шаблоне для этого уже есть метки сборок `vN-rc.K`, сверка выпускаемого с последней проверенной сборкой (`release.yml`) и подпись сборки.

### Кто куда пишет

У каждой роли свой файл, и правку его одобряет только её команда (`.github/CODEOWNERS`). Все правки — через запрос на слияние. Владелец репозитория состоит во всех командах запасным одобряющим, потому что GitHub не засчитывает одобрение собственного запроса.

| Роль | Файлы |
|---|---|
| Разработчик | `roles/developer.yaml`, `roles/developer-links.yaml` |
| Выпускающий | `roles/release-lead.yaml`, `releases/<N>/decisions.md` |
| Тестировщики | `releases/<N>/tests/rc.<K>.yaml` — один файл на сборку |
| Программа сборки | `now/` и `releases/<N>/shipped.md`; руками их не правят |

## Структура

Оперативное и накопительное лежат раздельно.

```
now/                    — ОПЕРАТИВНОЕ: состояние на сейчас; программа переписывает целиком при каждой сборке
  board.md              — табло: только цифры по стадиям, каждое число ведёт к списку
  lists/                — списки результатов, по файлу на стадию, и предложенные новые результаты
  completeness.md       — сверка полноты
roles/                  — ОПЕРАТИВНОЕ: что заявляют роли сейчас
  developer.yaml        — результаты и их статусы (снимок источников)
  developer-links.yaml  — какая запись списка изменений служит какому результату
  release-lead.yaml     — текущий отбор Выпускающего
releases/<N>/           — НАКОПИТЕЛЬНОЕ: по папке на выпуск; после выхода выпуска не меняется
  shipped.md            — что вошло в выпуск (собирает программа)
  decisions.md          — решения Выпускающего
  tests/rc.<K>.yaml     — отметки тестировщиков, один файл на сборку
tools/                  — build_board.py (сборка табло и сверка полноты), pii_scan.py (поиск личных данных)
.github/                — CODEOWNERS и проверка перед слиянием (publication-gate.yml)
```

## Что здесь не хранится

- Код шаблона — он в [FMT-exocortex-template](https://github.com/TserenTserenov/FMT-exocortex-template).
- Цели — они в [«Целях и сценариях»](https://github.com/MimEcoSys/PACK-digital-platform/blob/main/pack/digital-platform/07-map/DP.MAP.005-mcp-scenarios.md).
- Личные данные: репозиторий открытый. Без почты, телефонов и обращений пользователей с их данными; обращение — пересказом без имени.
- Секреты и ключи.
